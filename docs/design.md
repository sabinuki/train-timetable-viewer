# train-timetable-viewer 設計書

## 1. 目的

macOS に常駐させ、指定した駅・路線・方面の **現在時刻以降の発車時刻** をデスクトップに表示する。
PC で作業しながら、「何分に作業を切り上げれば何時発に乗れるか」を、時刻表を開かずに一目で判断できるようにする。

### 1.1 想定ユースケース

| ユースケース | 例 |
| --- | --- |
| 職場や学校から帰る | 退勤や下校の前に、乗れる電車から逆算して作業を区切る |
| 自宅から出かける | 出勤や外出の前に、最寄り駅の次発に合わせて家を出る |
| 外出先から移動する | カフェやコワーキングスペースで作業中に、次の予定に間に合う電車を確認する |

ユースケースごとに駅、方面、駅までの所要時間が変わるため、これらの組み合わせを「路線プロファイル」として登録し、切り替えられるようにする（F-11）。

## 2. 前提・制約

| 項目 | 内容 |
| --- | --- |
| コスト | 開発・運用ともに無料（有料 API、有料サーバー、Apple Developer Program 有料登録を使わない） |
| 実行環境 | macOS PC（オフラインやプロキシ下のネットワークでも動作すること） |
| 利用者 | 自分ひとり（配布・ストア公開はしない） |
| 表示 | デスクトップ上に常時表示し、表示と非表示をすぐ切り替えられること |

## 3. 要件

### 3.1 機能要件

| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-1 | 指定した駅・路線・方面の発車時刻のうち、現在時刻以降の N 本を表示する | 必須 |
| F-2 | 次の発車までの残り時間（カウントダウン）を表示する | 必須 |
| F-3 | 平日と土休日（祝日を含む）のダイヤを自動で切り替える | 必須 |
| F-4 | デスクトップ上に常時最前面で表示するフローティングパネル | 必須 |
| F-5 | メニューバーとグローバルショートカットで、パネルの表示と非表示を切り替える | 必須 |
| F-6 | 駅までの所要時間（徒歩分数）を設定し、「出発すべき時刻」を表示する | 必須 |
| F-7 | メニューバーに次の発車時刻（または出発すべき時刻）を表示する | 推奨 |
| F-8 | 出発すべき時刻の X 分前に通知する | 推奨 |
| F-9 | 種別（快速、各停など）や行き先で絞り込む | 推奨 |
| F-10 | ログイン時に自動起動する | 推奨 |
| F-11 | 複数の路線プロファイル（駅、方面、所要時間）を登録して切り替える | 推奨 |
| F-12 | ODPT API から時刻表を取り込む | 任意（フェーズ 2） |

### 3.2 非機能要件

- **オフライン動作**: 時刻表はローカルに保持し、表示中はネットワークに依存しない。プロキシ環境や回線断の影響を受けないようにする。
- **低負荷**: 常駐アプリなので、CPU とメモリの使用量を最小限にする（再描画は 1 秒または 1 分ごとのタイマーのみ）。
- **控えめな見た目**: 作業画面の邪魔にならないよう、小さく半透明にでき、クリックを素通しする設定も用意する。
- **プライバシー**: 利用状況などを外部へ送信しない。

## 4. 時刻表データソースの検討

| 候補 | 費用 | 長所 | 短所 | 採否 |
| --- | --- | --- | --- | --- |
| **ローカル JSON（手入力・変換）** | 無料 | 全路線に対応できる。オフラインで動作し、規約上の問題もない | 初回入力とダイヤ改正時の更新に手間がかかる | **採用（MVP）** |
| **公共交通オープンデータセンター（ODPT）API** | 無料（開発者登録が必要。承認まで数営業日） | `odpt:StationTimetable` で駅時刻表を構造化データとして取得できる | 対応事業者が限られる（東京メトロ、都営など）。JR 東日本などの提供範囲や利用条件は要確認 | **採用（フェーズ 2、取り込み用途）** |
| 駅すぱあと、NAVITIME などの商用 API | 基本は有料。無料枠は制限付き、または試用のみ | 全国の路線を網羅している | 無料という条件を満たさない | 不採用 |
| 乗換案内サイトのスクレイピング | 無料 | 全国を網羅できる | 多くのサイトは利用規約で禁止している。HTML の変更で壊れる | 不採用 |
| GTFS / GTFS-JP の静的データ | 無料 | 標準フォーマット | 国内では鉄道のデータが少なく、バス中心 | 不採用（必要になれば取り込み元として追加） |

**方針**: アプリ内部の時刻表はすべて「ローカル JSON」という 1 つの形式に統一する。データの取得元は `TimetableProvider` として抽象化する。

- MVP では、公式サイトの時刻表を見ながら JSON を手入力（またはスクリプトで整形）する。1 方面あたり平日と土休日の 2 種類で済む。
- フェーズ 2 では、対象路線が ODPT に対応していれば API から取得してローカル JSON に変換し、キャッシュする。API は「起動時とダイヤ改正時に取り込む」用途に限り、表示のたびには呼ばない。

> 対象駅・路線が ODPT に含まれるかは、実装前に [ODPT 開発者サイト](https://developer.odpt.org/) で確認する（§11 未決事項）。

### 4.1 祝日データ

土休日ダイヤの判定には、内閣府が公開している「国民の祝日」CSV（`https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv`、無料）を使う。

- ビルド時にアプリへ同梱し、起動時に年 1 回程度だけ更新を試みる。取得に失敗した場合は同梱版を使う。
- 年末年始（12/30〜1/3）など、鉄道会社が独自に土休日ダイヤで運行する日は設定で追加できるようにする。

## 5. 技術選定

| 項目 | 選定 | 理由 |
| --- | --- | --- |
| 言語 / UI | Swift 6 + SwiftUI（必要な箇所は AppKit） | macOS ネイティブで軽量。メニューバーとフローティングウィンドウを標準 API で実装できる |
| 対応 OS | macOS 14 Sonoma 以降 | `MenuBarExtra` と `SMAppService` を使えるようにするため |
| 常駐形態 | メニューバー常駐アプリ（`LSUIElement = YES`、Dock にアイコンを出さない） | 常駐しても邪魔にならない |
| 最前面パネル | `NSPanel`（`.nonactivatingPanel`、`level = .floating`） | 他のアプリのフォーカスを奪わずに最前面に表示できる |
| グローバルショートカット | Carbon の `RegisterEventHotKey` | アクセシビリティ権限が不要。外部ライブラリなしで実装できる |
| 自動起動 | `SMAppService.mainApp` | 標準 API |
| 通知 | `UserNotifications` | 標準 API |
| 設定保存 | `UserDefaults`（設定値）と Application Support 内の JSON（時刻表） | シンプル |
| 配布 | 自分で Xcode からビルドし、無料の Apple ID で署名してローカル実行する | 有料の Developer Program や公証（notarization）が不要 |

> **管理された PC の注意点**: 職場などで管理されている PC では、自作アプリのインストールや実行がポリシーで制限されている場合がある。導入前に確認すること。どうしても許可されない場合の代替案として、ブラウザの小窓で表示できる静的 HTML 版も検討の余地がある（本設計の対象外）。

## 6. 画面設計

### 6.1 メニューバー

```
[🚃 18:05 あと12分]        ← 次発（または出発すべき時刻）を常時表示
 ├ パネルを表示 / 隠す   ⌥⌘T
 ├ 路線切替 ▸ 〇〇線 △△方面
 ├ 設定…
 └ 終了
```

- 表示形式（「次発の時刻」「出発すべき時刻」「アイコンのみ」）は設定で切り替えられる。

### 6.2 フローティングパネル

```
┌──────────────────────────────┐
│ 〇〇駅  △△線  ××方面   平日 │
├──────────────────────────────┤
│ ▶ 18:05 快速 ××行   あと12分 │  ← 次発を強調
│      └ 17:57 までに出発       │  ← 徒歩 8 分の場合
│   18:12 各停 ××行   あと19分 │
│   18:20 快速 ××行   あと27分 │
│   18:31 各停 □□行   あと38分 │
└──────────────────────────────┘
```

- **表示件数**: 3〜10 本（設定可能）。
- **間に合わない列車**: 「出発すべき時刻」を過ぎた列車は薄く表示し、乗れる最初の列車を強調する。
- **表示・非表示の切り替え**: メニューバーの項目、グローバルショートカット（初期値 `⌥⌘T`、変更可能）、パネルの × ボタンで切り替える。
- **ウィンドウの挙動**:
  - `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]` とし、すべてのデスクトップ（Spaces）に表示する。
  - ドラッグで移動でき、位置とサイズを保存する。
  - 不透明度は 30〜100% の範囲で設定できる。
  - 「クリック透過」モード（`ignoresMouseEvents = true`）では、パネルの上から下のウィンドウを操作できる。透過中はメニューバーから解除する。
- **終電後**: 「本日の運行は終了しました」と表示し、翌日の始発を表示する。

## 8. データモデル

### 8.1 時刻表 JSON

```json
{
  "version": 1,
  "station": { "id": "example-station", "name": "〇〇駅" },
  "line": { "id": "example-line", "name": "△△線" },
  "direction": { "id": "outbound", "name": "××方面" },
  "validFrom": "2026-03-14",
  "source": "manual",
  "calendars": {
    "weekday": [
      { "time": "05:12", "type": "各停", "destination": "××" },
      { "time": "18:05", "type": "快速", "destination": "××" },
      { "time": "24:21", "type": "各停", "destination": "□□" }
    ],
    "holiday": [
      { "time": "05:20", "type": "各停", "destination": "××" }
    ]
  }
}
```

- `time` は **運行日基準の `HH:mm`** で表し、日付をまたぐ終電は `24:21` のように 24 時以降で表記する（ODPT や鉄道各社の時刻表と同じ慣習）。
- `calendars` のキーは `weekday`（平日）と `holiday`（土休日）を基本とする。土曜ダイヤがある路線向けに `saturday` も任意で持てる。
- `validFrom` はダイヤ改正日。改正の前後で複数のファイルを持ち、日付で切り替えられるようにする。
- `source` は `manual`（手入力）または `odpt`（ODPT から取得）。

### 8.2 Swift のモデル（概要）

```swift
struct Departure: Codable, Hashable {
    let minutesFromServiceDayStart: Int   // "24:21" → 1461
    let type: String?
    let destination: String?
}

enum CalendarKind: String, Codable { case weekday, saturday, holiday }

struct Timetable: Codable {
    let station: Station
    let line: Line
    let direction: Direction
    let validFrom: Date
    let calendars: [CalendarKind: [Departure]]
}
```

## 9. 主要ロジック

### 9.1 運行日の判定

- 鉄道の「1 日」は 0:00 ではなく、終電後に切り替わる。`serviceDayBoundary`（初期値 3:00）より前の時刻は **前日の運行日** として扱う。
  - 例: 0:30 の時点では、前日の運行日の `24:30` 以降を探す。
- 運行日に対して、次の順で `CalendarKind` を決める。
  1. 追加の休日（ユーザー設定）または祝日（内閣府 CSV）なら `holiday`
  2. 日曜なら `holiday`
  3. 土曜なら `saturday`（なければ `holiday`）
  4. それ以外は `weekday`

### 9.2 次発の算出

1. 現在時刻から運行日と、運行日基準の経過分を求める。
2. その運行日のカレンダーの発車時刻を二分探索し、`now` 以降の N 本を取り出す（絞り込み条件を適用）。
3. N 本に満たなければ、翌運行日の先頭から補う（終電後に翌朝の始発を出すため）。
4. 各列車について `leaveBy = 発車時刻 − 駅までの所要時間` を計算し、`now <= leaveBy` を満たす最初の列車を「乗れる次発」とする。

### 9.3 更新タイミング

- 毎分 0 秒に合わせたタイマーで再計算する。カウントダウンを秒単位で表示する場合のみ 1 秒ごとにする（設定）。
- `NSWorkspace.didWakeNotification`（スリープ復帰）、`NSSystemClockDidChange`（時刻変更）、`NSCalendarDayChanged`（日付変更）を受けたら即座に再計算する。
- パネルを非表示にしている間は、メニューバー表示に必要な計算だけを行う。

### 9.4 通知

- 「乗れる次発」の `leaveBy − X 分` に `UNTimeIntervalNotificationTrigger` を 1 件だけ登録し、再計算のたびに差し替える。
- 通知を出す時間帯（例: 17:00〜20:00）を路線プロファイルごとに設定できるようにし、移動する予定のない時間帯に鳴らないようにする。

## 10. 開発フェーズ

| フェーズ | 内容 | 完了条件 |
| --- | --- | --- |
| 0 | `TimetableCore`: モデル、運行日判定、次発の算出、単体テスト | 日付またぎ、祝日、終電後のテストが通る |
| 1（MVP） | メニューバー常駐、フローティングパネル、ショートカットによる表示切替、手入力 JSON の読み込み、徒歩分数 | 1 路線の次発と出発すべき時刻が表示される |
| 2 | 通知、絞り込み、ログイン時起動、不透明度とクリック透過、複数の路線プロファイル、設定画面 | 日常利用で手動操作が不要になる |
| 3 | ODPT からの取り込み（対象路線が対応している場合） | API キーを設定すると時刻表 JSON が生成される |
